# Task

## Goal

Produce a truthful presentation coverage matrix for `magic_orange_cat` and
`salad_cat`, covering every required gameplay state and move.

## Context

`A-VS-001` established source/runtime gameplay coverage but intentionally did
not certify production visuals. `A-RUN-005` remains externally blocked because
GitHub Rulesets cannot be enforced on the current personal private repository;
this is an accepted operational limitation, not evidence that CI is
server-enforced. Every change for this task must still run the checked-in
verification command where the runtime is available.

## Existing Behavior To Preserve

Presentation observes authoritative simulation state only. This audit must not
alter move timing, combat state, hitboxes, hurtboxes, damage, or asset runtime
behavior.

## Required Change

Create a matrix that maps each Golden Pair state/move to its production visual
binding or explicit fallback. Record source/static evidence separately from
runtime and human visual review. Convert every missing or uncertified item into
a discrete follow-up under `A-VS-003` through `A-VS-006`.

## Public/API Contract

None. The matrix is an evidence artifact and does not grant presentation or
art authority over gameplay.

## Implementation Constraints

Do not silently infer animation coverage from a sprite sheet existing on disk.
Do not label source inspection as a manual play/feel result. Do not modify
combat or roster data to make the audit appear complete.

## Edge Cases

An explicit fallback is valid only when it is intentional, named, and visibly
safe; a missing binding is not a fallback. Generated production assets must be
traced to their manifest/source contract.
