# Task

## Goal

Make the Golden Pair roster presentation resources resolve every required state
and canonical move to an explicit production animation key.

## Context

`A-VS-002` found that `salad_cat_presentation.tres` and
`magic_orange_cat_presentation.tres` contain the correct production scenes but
no state or move bindings. The resolver therefore falls back to `idle` or
`stand_light`, despite the production scenes supplying all required keys.

## Existing Behavior To Preserve

Presentation remains a read-only projection of authoritative fighter state and
move IDs. No combat timing, move data, collision, snapshot, replay, or roster
gameplay data may change.

## Required Change

Add explicit state/move bindings to both Golden Pair roster resources and add
focused coverage that proves each required key resolves without a generic
fallback.

## Public/API Contract

The roster `CharacterPresentationData` resources provide explicit mappings for
the existing canonical state and move identifiers.

## Implementation Constraints

Use only the existing production animation keys. Do not fabricate art or
change `FighterPresentationResolver` fallback behavior.

## Edge Cases

`charge` maps to `special_neutral`; Magic Orange Cat's L2/L3 special move IDs
also map to `special_neutral`. The asset source defect in Salad frames 038–040
remains visible and must not be concealed by a fabricated frame.
